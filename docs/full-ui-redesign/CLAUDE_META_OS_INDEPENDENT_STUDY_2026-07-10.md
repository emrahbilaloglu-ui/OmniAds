## A. Executive Verdict

### What Adsecute Meta must become

Adsecute Meta must become a **verified-execution, institutional-memory media-buying operating system**. Its wedge is not "smartest recommendations" — every competitor claims that and no expert buyer believes it on faith. The defensible wedge is already half-built in this repo and claimed by nobody else: **honest decisions with receipts**. [CURRENT] Every provider write is write-then-verify with `silent_failure` as a first-class audit status (`lib/meta/ads-write.ts` verification GET after every POST; `MetaAdsActionStatus` in `lib/meta/ads-action-log.ts`, with `verified_at`, `verification_payload`, `rec_id_origin`); missing data renders as em-dash, never zero; action semantics are server-owned (`lib/meta/rec-presentation.ts`: "The UI may format; it must not decide action semantics"); five persistence layers already journal decisions, responses, writes, snapshots, and transitions. Recommendations earn authority *through* that verification loop, not before it. Retention follows the same logic: once months of decisions, receipts, and outcomes live only here, the switching cost is the operator's own institutional memory.

### The one-screen morning product

[PROPOSED] One screen, four bands, opened every morning, answering the buyer's four-question ritual (what changed / what needs my hand / did yesterday take / what is waiting):

1. **Overnight receipt band** — a direct render of the existing digest contract (`readDecisionDigest()` in `app/api/meta/decisions-workspace/route.ts`: verified actions, silent failures, label flips, due deferrals). Silent failures are the loudest element on the page when present.
2. **Act Now — permanently sectioned by decision class** (creative rotation / campaign and ad-set money moves / integrity fires), per resolution D1. Selection is the D6 server contract: top-N per section (N=7 default) with `suppressedCount` and per-reason suppression receipts, so the queue typically renders a handful of cards per section — the owner's original "3–7 decisions" promise survives as the per-section experience, not a global cap. Exposure (real spend at stake) orders items within a section, and null exposure promotes to a visible "can't rank — investigate" band, never silently sinks.
3. **Due-backs** — deferrals whose `reappear_at <= NOW()` (already computed by the digest) plus compact Monitor section counts with the server's waiting reason.
4. **Yesterday's outcomes** — the most recent accrual results with the correlational caveat rendered (`lib/meta/outcome-accrual.ts` is explicitly correlational), linking into History.

### What it must not become

Five failure shapes, all evidenced in this repo's own history, are explicitly banned:

- **A reporting dashboard** — analysis the operator reads instead of decisions with receipts; the owner pack's stated anti-goal.
- **A card-wall** — marketing tiles that decorate rather than triage.
- **A spreadsheet** — the v2 panel spec produced exactly this and the owner rejected it ("reads like a dense data spreadsheet", `docs/full-ui-redesign/CODEX_DECISIONS_REVIEW_PROMPT.md` §2).
- **A fake-comparability single feed** — one interleaved rank across engines whose confidences are incomparable (v1 `confidenceScore` is 0–1; v3 `confidence` is an uncalibrated heuristic clamped to [40,95] via `clampConfidence`, `lib/creative-decision-engine/gates/types.ts`). The committed page's refusal — "no fake global rank across engines" (`components/meta/redesign/MetaPlatformPage.tsx`) — is product law, not a temporary state.
- **Autonomy theater** — [CURRENT] guardrail numbers exist and render (`DEFAULT_META_AUTOMATION_GUARDRAILS` in `lib/meta/automation-control-plane.ts`) but no write path reads or enforces any of them, and no executor exists: `auto_execute` is unreachable without manual DB writes. Automation UI that implies agency the system does not have is banned until the D14 floors are met.

### Stage sequence (gates, no dates)

- **Stage 1 — Trusted triage.** Sectioned Act Now with server top-N + suppression receipts (D6); assessment v1, creative grain only, five emitted states (D2); server-stamped `riskTier` mapping to existing confirmation ceremonies; `META_DECISION_RESPONSE_ACTIONS` extended with `rejected`/`overridden` + `reasonCode` + user attribution; the date-range replay leak closed (D13). **Gate:** date-free `decisionId` episode identity and attributed responses live.
- **Stage 2 — Memory.** `/platforms/meta/history` as a read-model union over the five existing journals with keyed joins; notification spine (in-app inbox + daily digest email; critical alerts immediate); qualified winner-browse from `engine_v3_decision_snapshots_daily` (D3). **Gate:** keyed joins fully replace the JSON-substring match, so History reads only from the five persisted journals; Replay reads only persisted decision snapshots (D13).
- **Stage 3 — Calibrated authority.** Per-grain versioned priority scores observed against matured outcomes; the cross-section "Top strip" as a selection mechanism only (D1); Promote-to-Main as a three-step lifecycle with persisted graduation records and `promotionBasis` (D7); Single Write Gateway with `ExecutionReceipt` verdicts. **Gate:** ECE ≤ 0.05 per label (the repo's own published gate, currently failed at 0.14); day-8 immature-attribution accrual bias fixed; `unknown_outcome` excluded from evidence.
- **Stage 4 — Bounded autonomy.** Per-action-class mode promotion under D14: n ≥ 30 per calibration cell, calibration gate, financial strata read only after attribution maturity, and a critical-error budget where any `silent_failure` trips the class circuit breaker. Every floor is hard. **Gate:** all four floors server-checked; rollback is forward inverse actions with their own verified receipts.

## B. Evidence-Backed Critique of the Current Product and Rejected Directions

### B.1 The committed product

The honesty substrate is real, rare, and largely wasted by the composition sitting on top of it. Eight defects define the gap. All are [CURRENT], verified at HEAD `2ddc00cf`.

| # | Defect | Primary evidence |
|---|---|---|
| 1 | 3,814-line page monolith | `components/meta/redesign/MetaPlatformPage.tsx` |
| 2 | HTTP self-fetch BFF; whole-page empty-shell failure mode | `app/api/meta/decisions-workspace/route.ts:22,54,498–499` |
| 3 | No composite priority at the v1 grain | `app/api/creatives/briefing/card-serialization.ts:334`; `app/api/meta/lane-classify/route.ts` |
| 4 | Grains never merge — and cannot honestly | `lib/creative-decision-engine/types.ts` `DecisionOutput`; `lib/meta/recommendations.ts:150` |
| 5 | Dead notification bell; no delivery substrate | `components/layout/topbar.tsx:25–30` |
| 6 | Anonymous, structureless decision responses | `lib/meta/decision-responses.ts:6` |
| 7 | Uncapped lanes; 203-item creative "Act Now"; post-cap counts | `app/api/meta/lane-classify/route.ts`; `docs/full-ui-redesign/DECISIONS_TRIAGE_BOARD_RATIONALE_2026-07-10.md` |
| 8 | Date-range replay leak with live writes (P0 honesty bug) | `lib/meta/snapshot.ts:1102`; `MetaPlatformPage.tsx:2859` |

**1. The monolith.** The entire Decisions surface is one 3,814-line client component (`MetaPlatformPage.tsx` at HEAD) owning topbar chrome, five lanes, filter state, mobile screens, write handlers, optimistic response reconciliation, and bulk flows. Every layout experiment becomes a ~1,900-line diff (the rejected working tree touches it +952/−934). This is why redesign attempts have been high-blast-radius rewrites rather than composable iterations — the architecture itself forces the oscillation documented in B.3.

**2. The self-fetch BFF and the 2026-07-08 incident.** The workspace route aggregates by HTTP self-fetching two internal routes with forwarded cookie/authorization headers (`readInternalJson` calling `/api/meta/account-pulse` and `/api/meta/lane-classify`); the file's own line-22 comment admits "the right long-term fix is to drop the HTTP self-fetch for in-process calls." On 2026-07-08 this design blanked the entire page: under the webpack dev bundler the self-fetch starved past its then-8s timeout and the sole failure mode fired — a whole-page "Meta briefing could not load" empty shell (root cause documented in `docs/full-ui-redesign/SOLO_CONTINUATION_PLAN.md`). The fix raised `WORKSPACE_UPSTREAM_TIMEOUT_MS` to 15s prod / 45s dev and added `retry: 2` — symptom treatment. A single aggregated GET means any upstream failure takes down Act Now, receipts, and posture banners together; this is the direct motivation for the D6 fetch split (Act Now selection contract; Monitor and History as separate paginated resources).

**3. No composite priority.** The owner's explainable composite (risk, opportunity, spend, confidence, time sensitivity) exists nowhere. The only numeric priority in the repo is creative-briefing-only (`buildBriefingPriorityScore`, with explainable `spendAtRisk`/`opportunityValue` inputs) and it never reaches the Decisions surface. At the v1 grain, server order is the snapshot ORDER BY (`decision_state` act>test>watch, `confidence_score` DESC, `rec_type` ASC in `lib/meta/snapshot.ts`), and the client re-sorts by raw spend (default `"money"` in `sortMetaRecs`). Act Now membership is a confidence gate, not a money gate (`confidenceScore >= 0.7 && !isInLearning && !isWithIssuesRec && !deferred`, `app/api/meta/lane-classify/route.ts`). A buyer triages by dollars at stake; the product currently triages by the engine's self-confidence.

**4. Grains never merge — correctly, but as a dead end.** The v1 engine speaks a 15-value label set (`MetaDecisionLabel`, `lib/meta/recommendations.ts:150`), the creative engine a 7-value set; their confidences are incomparable scales; and `DecisionOutput` carries no `campaignId`, `adsetIds`, or `thumbnailUrl` — the creative engine publishes no parent mapping at all. The committed page's refusal to fake a global rank is right. But the consequence as shipped is that creative decisions render as an appendix group whose primary CTA is a link to `/platforms/meta/creatives` labeled "Review" with an "Analysis only" authority chip (`MetaPlatformPage.tsx`) — triage dead-ends into another surface instead of resolving into a sectioned queue with real thumbnails and real actions.

**5. The dead bell.** The topbar bell is a `<button>` with an `aria-label` and no onClick handler, no badge, no data source (`components/layout/topbar.tsx:25–30`) — decorative chrome implying a capability that does not exist. There is no notification delivery system anywhere: the only notification-shaped contract, `MetaAutomationGuardrails.notificationPolicy` (default `"every_auto_action"`, `lib/meta/automation-control-plane.ts`), has no consumer that sends anything, and email infrastructure (`lib/email/mailer.ts`) is used solely for password reset. Every owner requirement downstream of delivery — immediate critical alerts, daily digest, mobile notification-to-action — currently has no substrate.

**6. Anonymous responses.** `META_DECISION_RESPONSE_ACTIONS = ["acted","deferred","undeferred","ignored"]` (`lib/meta/decision-responses.ts:6`) has no `rejected`, no `overridden`, no structured reason field, and the table records no user column. Three owner requirements die here at once: structured disagreement is unexpressible; History and approval attribution are impossible (any risk-tiered approval flow becomes client theater); and the shadow classifier the owner wants has no training signal, because disagreement is the training data.

**7. Uncapped lanes and circular counts.** No server cap exists on `actionNow` or `watching` (watching is literally the "rest" partition of the lane classifier); Healthy and Non-sales are capped by `.slice(0,18)`/`.slice(0,30)` *and then* counted from the capped arrays — so lane tab counts are circular, not inventory truth. Against the owner's "3–7 top decisions" promise, the live Grandmix check (2026-07-10, `DECISIONS_TRIAGE_BOARD_RATIONALE_2026-07-10.md`) recorded 7 Action Now, 22 Watching, 30 Non-sales, 1,071 Archive — and **203 actionable creative calls rendered without any cap**. No selection contract, no suppression receipt, no admission control exists; the "bounded ~70 rows" belief was an artifact of one account's current state.

**8. The date-range replay leak.** `readMetaDecisionSnapshotForRange` serves the newest snapshot *within the requested range* (`SELECT MAX(snapshot_date) … lib/meta/snapshot.ts:1102`). Select a custom past date range and the workspace serves month-old decisions — with live write buttons — under a lane note asserting "date range scopes metrics, not decisions" (`MetaPlatformPage.tsx:2859`). The owner's rule ("date range normally changes metrics, not the latest decision snapshot") is currently false in the product's own copy, and the operator can execute today's pause against last month's recommendation. Per D13 this is a P0 honesty bug: until metric-window and decision-snapshot reads are separated, past-dated views must render as "historical decisions — actions disabled."

### B.2 The rejected Codex triage-board experiment (uncommitted working tree)

The working tree (1,886-line diff on `MetaPlatformPage.tsx`, new `MetaPlatformPage.module.css`) is owner-rejected. It deserves an honest autopsy, because parts of it are the best UI thinking in the repo's history.

**What it got right.**
- **Bounded first render with receipts.** `MetaRevealReceipt` ("Showing N of M … hidden to keep this view bounded", `data-testid="meta-reveal-receipt"`) is the first attempt anywhere to state suppression honestly, directly anticipating D6's suppression-receipt contract. Its limitation: the bounding is client-side over a payload that still ships everything — cosmetic, not architectural.
- **Quiet rows.** Rebuilding Healthy/Archive as compact `MetaQuietEntityRow`/`MetaArchiveEntityRow` lists demotes non-actionable inventory so it stops competing with decisions — the correct instinct behind the Healthy/Non-sales demotion this report adopts.
- **Honest missing-preview handling.** `creativePreviewUrl` checks fields the live `DecisionOutput` does not carry and renders `data-preview-state="missing"` rather than inventing an image.
- **Contract discipline.** It preserved all five server-owned lanes, every write path, and the invariant that "the UI still never computes buyer action."

**Why it was rightly rejected.**
- **Client-built scope rail.** `MetaScopeRail` derives campaign→ad-set navigation client-side from the loaded lane payload (`buildMetaScopeCampaigns`), and is disabled entirely in the creative lens because "this engine does not provide campaign or ad-set mapping." Navigation topology became derived UI state — violating the server-owned-semantics doctrine and going blind at exactly the grain where scoping matters most. The winning position: scope is a server contract or it does not ship.
- **Two-column board.** The `boardGrid` two-column layout loses to D12: a ranked triage queue must have one unambiguous scan order, and at 1440px two columns plus the evidence inspector are mutually exclusive — opening an item reflows the queue mid-triage. Single-column with a permanently reserved inspector (reusing the committed `useMinWidth(1440)` push pattern) wins; the losing two-column position (owner pack, and the experiment) fails on that viewport arithmetic.
- **No product spine.** It restyled the queue without changing what the queue knows: still no composite priority (cards ordered by spend), no server `riskTier` (every write keeps the same flat confirm), no Act Now/Monitor/History IA (it retains five lanes with Healthy and Non-sales as top-level tabs), no impact contract, no structured Defer/Reject/Override. Its own rationale doc condemned its predecessor as "accurate but product-poor"; the board fixed the density and kept the poverty. The exact owner rejection wording is not recorded in-repo (UNVERIFIED beyond this study's brief).

### B.3 Prior panel-spec and design-fidelity failures

The redesign history (`docs/full-ui-redesign/`) is a case study in process gates mistaken for product definition.

- **Green gates ≠ design.** The eight-phase Codex port ended with all gates green — typecheck, lint, 3,697 vitest tests, Playwright smoke. The coverage ledger later carries its own self-correction: it is "a route/render coverage ledger only… must not be used as proof that a surface matches the reference" (`ROUTE_COVERAGE_LEDGER_2026-07-07.md`). The adversarial audit that followed (`DESIGN_FIDELITY_LEDGER_2026-07-08.md`) delivered the blunt verdict: ~52% table-average reference fidelity, "Nothing here is design-complete," Decisions at 66%, Mobile at 31%. A subsequent 16-agent re-baseline (`SOLO_CONTINUATION_PLAN.md`) found the 52% figure itself stale (real ≈80%) — the measurement apparatus failed in both directions, because nothing in the pipeline compares rendered composition against a reference. The Playwright smoke asserts status <500, no fatal markers, and ≤2px overflow (`playwright/tests/full-ui-redesign-smoke.spec.ts`) — structurally incapable of catching a design failure.
- **Layout oscillation without a product definition.** Bands → grid → spreadsheet → cards: the v2 panel spec and its addendum mandated a fixed-track columnar grid with an explicit "NO card/tile grid" rejection list (`DECISIONS_REVISION_PROMPT_v2.md`); it was implemented; the owner rejected the result as "a dense data spreadsheet" (`CODEX_DECISIONS_REVIEW_PROMPT.md` §2). Codex's board then over-corrected toward cards and was rejected too. Each attempt answered the previous complaint rather than a stable product definition — the definition Sections C–E of this report exist to supply.
- **Honest-data starvation.** Every "calm" layout died of the same missing contracts, documented in the free-judgment brief itself: no money-at-stake field (it is raw spend), no sparkline series, no per-row age/delta, no thumbnail or parent mapping on `DecisionOutput`. The designs did not fail aesthetically; the payload could not feed the composition. The corrective ordering is the owner pack's own: contracts and taxonomy first, then screens.
- **Process constraint, recorded.** The mega-prompt multi-phase execution model failed outright and is banned by standing project instruction (single phase, single branch, single review) — the staging in Section A is expressed as gates partly for this reason.

## C. Jobs-to-be-Done and Workflow Map (Experienced Media Buyer)

The primary persona is an experienced Meta media buyer running one to three brands at meaningful spend. Their day is a set of recurring loops, not a dashboard visit. Each loop has a trigger, an entry surface, a bounded set of decisions, and an exit condition — and each maps to one operational area (Act Now / Monitor / History) or specialist surface (Creative Studio / Launchpad / Automation). These loops are why Act Now stays permanently sectioned by decision class (D1): the jobs occur at different moments and altitudes, and an interleaved feed would force context-switching inside a ranked list.

### C.1 The daily morning triage loop (the 8am sequence)

**Trigger:** start of working day. **Entry surface:** Decisions command center, Act Now. **Exit condition:** every surfaced item is acted, deferred, or rejected with a reason — Act Now reads empty or explicitly parked.

The concrete sequence, in order:

1. **"Is anything broken?"** — scan the posture banner strip. [CURRENT] The product's strongest capability today: blocking banners for `tracking_write_gate`, `snapshot_health`, and `meta_write_kill_switch` built by `workspaceBanners()` in `app/api/meta/decisions-workspace/route.ts`, anomaly cards from `lib/meta/anomalies.ts`, and honest write verification including `silent_failure` status in `meta_ads_action_log`. [PROPOSED] The fire surface splits by altitude (D1): posture-level fires (tracking write gate, kill switch, snapshot health) remain blocking banners, while entity-level integrity fires (anomalies, delivery/policy breaks) form the Integrity fires section of Act Now — decision cards, not banners. The freshness banner becomes worst-of a named registry of the real freshness systems, each inspectable.
2. **"Am I pacing, at what efficiency?"** — one glance at the pulse. [CURRENT] `MetaPulsePayload` already carries `mtdSpend`/`mtdTarget`/`dayPace` and ROAS vs target with `target_source: "commercial_truth"|"account_median"|"none"` (`components/meta/redesign/types.ts`). Sufficient; do not expand.
3. **"Did yesterday's calls land and pay?"** — read the digest. [CURRENT] `readDecisionDigest()` (same route) returns label flips, verified vs silent-failure action counts, and due deferrals — the right raw material, currently rendered below the pulse rather than as the second element. [PROPOSED] Digest becomes the second strip; due deferrals push back into Act Now.
4. **"What do I act on today?"** — triage Act Now section by section, in the D1 three-section order: integrity fires (entity-level anomalies, delivery/policy breaks), then money moves (campaign/ad-set pause, bid, scale), then creative rotation (promote/cut/refresh with real thumbnails). [CURRENT] Today's gate is confidence, not money: Action Now = `confidenceScore >= 0.7 && !isInLearning && !isWithIssuesRec && !deferred` (`app/api/meta/lane-classify/route.ts:1273-1279`), and the default client sort is spend (`MetaRowSort` default `"money"`, `MetaPlatformPage.tsx`) — a proxy for exposure, not exposure. [PROPOSED] Server top-N per section (N=7 default) ordered by exposure within section, with `suppressedCount` and per-reason suppression receipts (D6, D8); nulls promote to a "can't rank — investigate" band, never sink.

**Decisions taken:** pause, bid change, defer, reject/override with `reasonCode`, route-to-Launchpad. **Writes:** [CURRENT] `execute_pause` → `POST /api/meta/adsets/{id}/pause`; `execute_bid` → `apply-bid` with typed `bidAmountMinor`; operator responses → `POST /api/meta/recommendations/respond` (`acted|deferred|undeferred|ignored`; deferral = `let_cook_24h`, 24h `reappearAt`). Every provider write returns a verified receipt.

- **Weekly review.** [CURRENT] No surface or read model exists; the owner pack specifies the agenda (decision quality, deferrals, financial outcomes, winner movement, automation safety) but the five journals it would read are unjoined, and `meta_decision_responses` rows are not user-attributed. [PROPOSED] The History read-model union with keyed joins and date-free `decisionId` episode identity is the prerequisite; the ritual surface is built on it.
- **Monthly economics.** [CURRENT] Commercial targets are read with no age predicate; the >30-day staleness rule in `lib/business-commercial.ts` is unwired, so a stale target still renders as highest-trust `commercial_truth`. [PROPOSED] Stale targets demote `truthSource` and surface as a recalibration prompt.

| 9 | Supervise automation | [CURRENT] Readiness gate ignores sample size; calibration fails its own gate (ECE 0.14 vs 0.05) | [PROPOSED] Per-action-class modes with D14 hard floors; [FUTURE] guardrailed auto-execution |

### C.4 Jobs the product must NOT do in v1

- **No AI copilot.** Explicitly deferred by the owner; no conversational layer, no recommendations outside the versioned engines.
- **No cross-account portfolio.** Decisions stays scoped to the single selected account; multi-brand operators switch accounts, they do not get an aggregate surface.
- **No impact scenarios on cards (D10).** Exposure — real spend at stake — is the headline number. Estimated impact is an inspector-only three-state contract (`unavailable | exposure_proxy | modeled`); since no current field supports `modeled`, v1 renders the honest "cannot be calculated from current evidence" statement, never a dead card slot.
- **No interleaved cross-grain ranked feed (D1)** and **no cohort-relative winner declarations (D3)** until the evaluation-scope object exists — "Winner" is banned when truthSource is `global_default` or `account_baseline_thin`.
- **No raw formula editing.** Strategy control is preset-only (Conservative / Balanced / Aggressive); live formulas change only through versioned release.
- **No auto-execution.** v1 is approval-based; promotion to stronger automation modes is gated by the D14 floors, all currently unmet.

## D. Recommended Information Architecture

### D.1 Area model: three operational areas, two routes

[CURRENT] The Decisions surface encodes state as five top-level lane tabs — `MetaLaneView = "action" | "watching" | "healthy" | "nonSales" | "archive"` in the `lane` URL param, entity focus in `entity` (`components/meta/redesign/MetaPlatformPage.tsx:98`, `parseMetaLaneView:144`, `entity` at 1903). The sidebar label already reads "Decisions"; only the internal nav-item id remains `"pulse"` (`components/layout/nav-items.ts:143`, label resolved via `lib/i18n.ts:117`). No History surface exists: `lib/meta/history.ts` exports only retention constants; the journaling substrate is split across five unjoined stores (`meta_ads_action_log`, `meta_decision_responses`, `meta_decision_action_outcome_logs`, the two daily snapshot tables, `engine_v3_decision_events` — the last consumed by no UI).

[PROPOSED] Act Now and Monitor are views over one live decision population; History is a different data shape (a paginated journal). Therefore: **two routes, three areas** — not three sibling routes. This delivers the owner's three-area model while preserving decision-permalink permanence: an item's address must not change when its state does.

**Permanent legacy aliases** (the existing parser defaults unknown lane values to "action", so aliasing is cheap; old links never break): `lane=action → area=act`; `lane=watching → area=monitor`; `lane=healthy → area=monitor&segment=healthy`; `lane=nonSales → area=monitor&segment=out_of_scope`; `lane=archive →` redirect to `/platforms/meta/history?kind=structures`. Sidebar hygiene: the user-facing label already reads "Decisions"; the only remaining rename is the internal nav-item id `"pulse"` → `"decisions"` (`nav-items.ts:143`) — an id change, never a route rename.

**Permalink grammar.** `?entity=<id>` remains the address of a decision; the same id resolves the same evidence inspector from Act Now, Monitor, or a History row (back-linked via `rec_id_origin`, already persisted on `meta_ads_action_log`). [CURRENT] This permanence does not exist yet: deep-link restore searches only `[...actionNow, ...watching, ...nonSales]` (`MetaPlatformPage.tsx:2368`) — healthy, archive, and creative-grain items never resolve, and any item cut by a lane cap is unaddressable. [PROPOSED] An entity resolver with fetch-by-id fallback is a named build item, not an existing property. Its companion prerequisite is the date-free `decisionId`: today's fingerprint embeds the snapshot date (`metaOutcomeFingerprint` = `meta_v1|businessId|scopeType|scopeId|recType|snapshotDate`, `lib/meta/outcome-accrual.ts:42-50`), so a decision persisting a week has seven identities and no stable address.

### D.2 Act Now: permanently sectioned, server-selected

Per resolution D1, Act Now is **permanently sectioned by decision class** — creative rotation, campaign/ad-set money moves, integrity fires — never one interleaved ranked list. The merge-after-calibration position (owner pack end-state) loses: triage jobs occur at different loop moments, automation guard budgets and circuit breakers are action-class-keyed, and committed code already encodes "no fake global rank across engines" (grouped rendering in `MetaPlatformPage.tsx`). [FUTURE] A calibrated composite score may *select* items for a compact cross-section "Top strip" with per-grain quotas and suppression receipts, and may order sections internally — it never renders one merged queue.

Per resolution D6, Act Now needs a **server-side selection contract**, which no code contains today. [CURRENT] The v1 lane is predicate-bounded, not count-bounded (`confidenceScore >= 0.7`, `app/api/meta/lane-classify/route.ts:1273-1279`); the creative section has no server cap at all — 203 actionable creative decisions on the live account; and lane counts are computed **after** the caps (`.slice(0,18)` at 1316, `.slice(0,30)` at 1335, `counts` from the sliced arrays at 1400-1406), so tab badges report the cap as the population. [PROPOSED] The contract: server-owned **top-N per section** (N=7 default), ordered within-grain (reusing `buildBriefingPriorityScore`, `app/api/creatives/briefing/card-serialization.ts:334`, stamped `within_grain_heuristic` per D8); a `suppressedCount` plus a per-reason **suppression receipt** on every section ("Showing 5 of 203 creative decisions — full queue in Creative Studio"), remainder addressable, never dropped; all counts computed **pre-cap**. This overturns the Round-2 one-payload consensus, whose "≈70 bounded rows" evidence was circular — the payload is small only because it truncates; `actionNow`/`watching` are uncapped (watching is the "rest" partition, route line 1280), and the same fan-out pipe produced the 2026-07-08 empty-shell incident.

### D.3 Monitor and History: pagination contracts

**Monitor** [PROPOSED] is a separate cursor-paginated resource with typed filters, so its volume can never blank Act Now. Its structure reuses the server-owned `watchSegment` keys that already exist (`unlabeled | missing_target | learning | recently_changed | deferred | issues | mid_confidence | insufficient_signal | other`, `WATCH_SEGMENT_META` in `lane-classify/route.ts`); "why waiting" is served per segment; "when reevaluated" is a new contract field (deferrals already carry `reappearAt`). Because the pack's own routing rules generate inflow in the hundreds, evidence-shortfall and cohort-imbalance items enter Monitor at **aggregate grain** — one item per ad set/cohort with member counts — individual grain reserved for deferred/issues/recently-acted. Non-sales is a named Monitor segment ("Out of sales scope"), not a filter chip: it is a different cohort with different units, and a filter implies comparability the engines refuse.

**History** [PROPOSED] is the new additive route, backed by a paginated read-model union over the five existing journals with **keyed joins** replacing the current evidence-trail JSON-substring match. Archive rows leave the workspace payload on day one: [CURRENT] all 1,071 archive rows serialize into every workspace fetch (built uncapped at `lane-classify/route.ts:1336-1339`) while the client renders 30 (`.slice(0,30)`, HEAD:3444) — a TTFB tax on every triage load and 1,041 unreachable rows. The workspace ships `counts.archive` (true total) only; closed structures live in History as `kind=structures`, per the owner's "old/closed structures live in History search."

### D.4 The collapsible scope rail

[PROPOSED] The rail is a **structure browser decorated with decision counts**, not a decision-derived tree. The rejected experiment's `MetaScopeRail` built its tree client-side from loaded lane rows — omitting any structure without a current decision and inheriting lane caps. Instead, the rail reads the warehouse sources that already exist (`getMetaCampaignsForRange`, `lib/meta/campaigns-source.ts:55`; `getMetaAdSetsForRange`, `lib/meta/adsets-source.ts:24`), returning campaign→ad-set structure with per-node area counts — derived inside the workspace response or a shared cache, since lane-classify already runs the same queries on first paint. Selection writes a display token to the URL (`scope=c:<id>` / `scope=as:<id>`); it **narrows, never recomputes** lanes (existing doctrine: client-side narrowing only) and never hides account-level calls. It is search-first, virtualized, count-decorated — the current 12-option campaign picker silently omits most campaigns (`campaignOptions` `.slice(0,12)`, HEAD:1976) and is retired. The rail is **disabled for the creative grain with an explicit notice** until `DecisionOutput` gains parent mapping: [CURRENT] `campaignId` exists on `CreativeInput` (`lib/creative-decision-engine/types.ts:228`) but `DecisionOutput` carries only `creativeId` — no campaign/ad-set/thumbnail fields — so a creative decision cannot honestly participate in structure navigation today.

### D.5 Saved View vs Evaluation Scope: two objects, two names

### D.6 Global search and saved scopes at scale

## F. Canonical Priority Model Requirements

### F.1 [CURRENT] Priority exists twice, both partial, neither on the Decisions surface

Two priority mechanisms are shipped, and neither serves the command center the owner describes.

- **Categorical priority (V2.1 bridge).** `derivePriority` in `lib/creative-decision-center/v3-bridge.ts:386-407` emits `high | medium | low` from data-health degradation, label, and confidence thresholds. It structurally **never emits `critical`** even though `critical` is in the contract union — a storm of simultaneous hard actions cannot escalate.
- **Numeric priority (briefing API only).** `buildBriefingPriorityScore` in `app/api/creatives/briefing/card-serialization.ts:334-389` computes `(spendAtRisk + opportunityValue + spend × exposure-floor) × confidenceFactor × severityWeight × actionWeight`, where `spendAtRisk = spend × max(0, 1 − ratioToTarget)` for cut and `opportunityValue = spend × max(0, ratioToTarget − 1)` for scale, returning explainable `inputs`. This is the best priority artifact in the repo: currency-denominated exposure proxies, no invented counterfactuals, every component disclosed.
- **The Decisions surface has no composite score at all.** V1 recs, anomalies, and v3 creatives render as separate groups; the committed guard comment in `components/meta/redesign/MetaPlatformPage.tsx:1553` (rendered as an on-surface note at line 3269) states the rule verbatim: "no fake global rank across engines."

Three defects poison any naive composite today: (a) two incompatible confidence scales — v1 uses 0–1 (with a fabricated `?? 0.4` default persisted at write time, `lib/meta/snapshot.ts:216`), v3 uses 0–100 clamped to [40,95] (`clampConfidence`, `lib/creative-decision-engine/gates/types.ts:56-65`); (b) neither is calibrated — published hard-bucket weighted ECE is **0.14 against the repo's own 0.05 gate** (`docs/creative-decision-center/READINESS_SCORECARD_2026-07-06.md:43-44`), and the calibration study's verdict is "No production confidence-threshold or formula change is supported by this phase" (`docs/creative-decision-center/CONFIDENCE_CALIBRATION_SOURCE_MODE_SUMMARY_2026-07-06.md`); (c) the shipped score zero-codes missing money — `safeNumber` maps null/non-finite spend to `0` (`card-serialization.ts:107-109`), so an item with unknown exposure silently sinks to the bottom of the very queue that should surface it.

### F.2 [PROPOSED] `PriorityContract v1`: promote the briefing score shape, per grain, versioned

The canonical priority model is not a new invention; it is the existing `buildBriefingPriorityScore` shape promoted to a versioned server contract and replicated per grain:

```
PriorityContract v1 = {
  score: number | null,
  band: high | medium | low,
  inputs: { spendAtRisk, opportunityValue, spend, confidenceFactor, severityWeight, actionWeight },
  modelVersion,
  comparabilityDomain: "creative_v3" | "meta_v1",
  semantics: "within_grain_heuristic" | "calibrated",
  displayTier: "band" | "numeric"
}
```

Rules, per D8:

- **`comparabilityDomain` is mandatory and machine-checkable.** The UI may order together only items whose domains are equal. This turns "no fake global rank" from a code comment into a contract the renderer cannot violate.
- **`within_grain_heuristic` vs `calibrated` are distinct semantics, not a quality dial.** Under `within_grain_heuristic` (everything today), the numeral is inspector-only; cards show band + rank position. The Round-1 decision-scientist proposal to display stamped numerals on cards was conceded to the visual-systems objection: a colored "87" beside a "62" from another engine is comparability-by-adjacency, and stamps do not survive scanning. `calibrated` semantics — and with it `displayTier: numeric` — unlocks only per label×grain behind the acceptance metrics in F.5.
- **A v1-grain score is buildable honestly.** Spend, ROAS, and operator targets exist at campaign/ad-set grain (`lib/meta/commercial-targets.ts`), so the same currency-exposure construction applies. What it may not do is reuse v1's `confidenceScore` as a factor while the `?? 0.4` fabrication persists at write time.

### F.3 [PROPOSED] The honest degraded Act Now ordering

Until calibration exists, Act Now orders **within each section** (D1: sections are permanent) by a rule fully computable from current fields:

1. **Safety tier first.** Verified safety/truth failures — tracking-gate failures, kill-switch states, stop-loss cuts with mature spend, stale hard-ceiling — always outrank economics. These map to guard classes that already exist server-side.
2. **Currency exposure second.** `spendAtRisk`/`opportunityValue` in account currency is the one honestly shared unit. Exposure orders items within a section and orders the section summary tiles — never an interleaved cross-section list.
3. **Confidence renders as a chip, never as a rank input.** Band + top contributing penalties ("Medium — thin baseline, stale lifecycle"), consistent with the confidence contract in Section H.
4. **Time sensitivity is a tier-promoting flag, not a score factor.** Only verifiable signals qualify: deferral `reappear_at` expiry (server-arbitrated today), the `opportunity_window_open/closing` badges, learning-phase exit. No deadline field exists at either grain; a "time sensitivity" multiplier would be fabricated.

**Null-exposure promotion rule (D8, mandatory).** Missing exposure is missing data, and missing is never zero. A null-exposure item **promotes** into a visible "can't rank — investigate" band at the top of its section; it never silently sinks. The current `safeNumber → 0` behavior in the shipped score is a named defect to fix, not a precedent.

**Hierarchy dedup requirement.** V1 recommendations are campaign/ad-set-level with aggregated spend; a parent's `spendAtRisk` structurally contains and double-counts its own creatives' exposure. Within-section ordering must suppress or group child items under an active parent decision, and any account-level aggregate exposure figure ("$X at stake today") requires hierarchy dedup first — never sum overlapping exposure.

The section header states the rule honestly: "Ordered by money at stake — cross-engine priority is not yet calibrated."

### F.4 What is IMPOSSIBLE until calibration — stated bluntly

- **The owner's five-component composite score (risk/opportunity/spend/confidence/time-sensitivity) cannot ship.** Confidence is uncalibrated (ECE 0.14 vs the 0.05 gate; hard-action calibration "remains unmeasured" — all 80 replay business-days ran `runtime_sql_fallback`), the two grains' confidences are different scales with different construction, and time-sensitivity has no data source beyond badges and deferral timers. Multiplying by "confidence" today multiplies two different uncalibrated quantities. The composite survives only as the F.2 contract's future `calibrated` state.

Even after calibration, the composite's role is *selection* (F.5), not interleaving: triage jobs occur at different loop moments, guard budgets are action-class-keyed, and the committed code already forbids the fake global rank. The losing position — merge-after-calibration as the end state (owner pack line 30) — is preserved only as the Top-strip selection mechanism and is flagged in Section O.

Per D10, cards carry exposure as the headline number; the inspector renders the three-state contract `unavailable | exposure_proxy | modeled`, which in v1 means the literal statement "cannot be calculated from current evidence" — never a dead slot on cards.

"Held winner status N days" is claimable only within one era; a cross-era "all-time winner" aggregate is fabricated continuity and is banned. Two survivor caveats inherit into duration claims: cut creatives stop snapshotting, and the prune job deletes only same-day rows for absent creatives (`decisions-job.ts:256-283`) — duration metrics measure survivors, and copy must say so. Promotion (D7) splits creative history across two ad ids; winner history must join on creative/post identity (`creative_id`/`object_story_id`), never ad id, or graduated winners vanish from their own history.

### G.8 The 90-day media constraint on visual winner archives

`META_CREATIVE_MEDIA_RETENTION_DAYS = 90` (`lib/meta/history.ts:3`; creative warehouse rows persist 455 days, decision snapshots indefinitely). The owner's 7/28/90/**all-time** Historical Winners filters therefore cross a hard media boundary: beyond 90 days the decision evidence survives but the visual does not. Contract: (a) declaring a creative a current winner — and any graduation record (D7) — **pins a media copy** exempt from retention pruning, so the archive stays visual for items that earned it; (b) rows whose media aged out before pinning existed render as **metadata-only** entries (label, ratio-to-target, truth source, era) with an explicit "media no longer retained" state — never a broken thumbnail, never a silently re-fetched lookalike. Creator-facing surfaces (Section I) inherit the constraint: no external share may promise a visual archive the retention policy cannot back.

### H.1 Decision card anatomy

**[CURRENT]** The committed card (`components/meta/redesign/MetaActionCard.tsx`) already has the right skeleton: server-owned action semantics via `actionAuthorityForRec` reading `actionKind`/`primaryActionLabel` stamped in `lib/meta/rec-presentation.ts` ("UI may format; it must not decide action semantics"), `chips.slice(0, 3)` with "+N" overflow, a toned money-at-stake line, and a confidence band pill. Its defect is signal load: ~6–7 elements per row, ≥3 colored, before the three-axis taxonomy even lands.

**[PROPOSED]** One card grammar, all grains:

1. **Left rail** — rank position within its section, ordinal only (numeric priority scores never render on cards per D8; server order today is the snapshot `ORDER BY` in `readMetaDecisionSnapshotForRange` (`lib/meta/snapshot.ts`: `decision_state` act>test>watch, `confidence_score DESC`, `rec_type ASC`), so ordinals ship only once tier+exposure ordering exists — an ordinal over a spend sort launders a sort into a ranking).

5. **Fact strip** — Spend · ROAS vs target (`ratioToTarget`) · CPA · Purchases · confidence *band as neutral text*. **Exposure (real spend at stake) is the headline number; estimated impact is off the card entirely (D10)** — the inspector carries the three-state impact contract, and v1 renders "cannot be calculated from current evidence" there, never a dead slot.
6. **Right action rail** — primary button + Defer + overflow. Exactly one semantically colored element per row: the action chip, hued by server `consequenceTone` (Promote is never green).

**Honest height math (binding for grading):** ~115px text card, ~128px chrome above the queue → **5 cards default at 1440×900; 4 with fact strips; 3–4 when creative thumbnail cards are present** (interaction-designer and high-volume red-team arithmetic, converged). ### H.3 Monitor item anatomy

### H.4 History journal

**[CURRENT]** Five journals persist and none has a surface: `meta_ads_action_log` (with `verifiedAt`, `silent_failure`), `meta_decision_responses`, `meta_decision_action_outcome_logs`, the two engines' daily snapshot tables (v1 + `engine_v3_decision_snapshots_daily`), and `engine_v3_decision_events` (previous/current label + confidence). The Archive lane shows closed entities, not decision transitions. Two structural defects: `lib/meta/evidence-trail.ts` joins action logs by `rec_id_origin` OR JSON-substring of scope id — a heuristic no journal may inherit; and outcome windows are 7d (v1, `lib/meta/outcome-accrual.ts` — accrual runs at snapshot_date+8, i.e. on immature attribution) and 7/14d (v3, `lib/creative-decision-engine/jobs/decision-outcomes-job.ts`); no 1/3-day window exists.

**[PROPOSED]** `/platforms/meta/history` (additive route): a read-model **union of the five journals** into typed entries — write, response, label-flip, outcome, structure (the `structure` kind absorbs the Archive lane's 1,071 closed-structure rows, per Section D) — reverse-chron, virtualized, with type/entity/date filter chips and search. Rollback is never a distinct entry kind: it renders as a write entry linked to its original via `rollbackOf` (J.8) — a forward inverse action with its own verified receipt. Keyed joins replace the substring match; **date-free `decisionId` episode identity is the prerequisite** (fingerprints embed `snapshotDate` today), so one episode threads recommendation → response → write → receipt → outcomes.

Outcome columns at 1/3/7/14 days, with the **check-type-bound-to-window rule**: 1/3-day cells may carry only *mechanical* verifications (delivery state changed, spend stopped, budget applied); *economic* readings (ROAS/CPA deltas) render only at 7/14 days after attribution maturity, else "accruing — Meta-attributed." Day-1 economics are noise and the current day-8 accrual bias must be fixed before outcome cells feed anything upstream (D14).

**Confounding-event annotation (adopted, creative lead's shape):** an operator-recorded, append-only account-level event annotation — offer/price change, site outage, tracking change, external promo — persisted as date + type + free text. Annotations render as timeline markers in History and as caveat context in the inspector's outcome precedent; any 1/3/7/14d outcome window overlapping an annotated event carries an explicit "confounded by {event}" caveat and is **excluded from promotion-evidence strata** (D14, J.6). Without this object, every outcome cell silently attributes external shocks to the decision.

Disagreement with attribution: extend `META_DECISION_RESPONSE_ACTIONS` (today exactly `["acted","deferred","undeferred","ignored"]`, `lib/meta/decision-responses.ts:6–11`) with `rejected`/`overridden` plus a structured `reasonCode` enum; Defer = one click + duration; Reject/Override = one forced reason chip, free text optional. **Defect (critical): responses are anonymous** — `meta_decision_responses` has no user column (`lib/migrations.ts:3010–3018`) while `meta_ads_action_log.requestedBy` is populated on every provider write. Add `user_id` now; History can never answer *who deferred* until it lands.

### H.5 Evidence inspector

**[CURRENT]** The disclosure layers exist but are flat: cards show a reason string; `MetaDrillDrawer` shows `evidenceTrail` (28d ROAS history, `peer_comparison` p10/p50/p90, `recent_changes`, `age_days`) and `empiricalOutcomeSummary`; creative decisions carry `DecisionPredicateBlocker` near-miss predicates (`lib/creative-decision-engine/types.ts:638`). **[PROPOSED]** Three strictly additive layers:

- **L2 (inspector, default open):** verifiable facts, each with per-fact provenance (source field, snapshot date, window): metric table, ROAS sparkline, peer p10/p50/p90, recent changes, near-miss blockers ("Needs N more purchases"), outcome precedent. ### H.6 Receipts

**[CURRENT]** `meta_ads_action_log` records `verifiedAt` and `silent_failure`, but there is no unified receipt object; the morning digest undercounts by design — all four digest queries are `LIMIT 20` and `labelFlips.count = labelRows.length` (`app/api/meta/decisions-workspace/route.ts:282, 387`), so a 300-flip day reports exactly 20; and digest failure renders as one muted line (`MetaPlatformPage.tsx` HEAD:1468–1469), silently disarming the silent-failure alarm.

**[PROPOSED]** Every provider write returns an `ExecutionReceipt` with verdict `verified_success | silent_failure | failed | unknown_outcome` — `unknown_outcome` (crash between POST and verify) is the dangerous class the owner-pack taxonomy omits. The receipt is a short immediate status expanding to: provider result, changed value (old → new), timestamp, and the audit record (who, from which surface, under which ceremony). Ads Manager links are **built from provider-returned ids** — never described as "verified permalinks," because no link is provider-checked; if no real id exists, the control is absent. Rollback rows never claim success without a provider-verified inverse receipt. Fixes bound to this contract: `COUNT(*)` alongside every `LIMIT` so digest counts are true totals with "and N more"; digest-unavailable becomes a warning banner ("Last night's writes could not be verified — check History"), never a muted whisper, with zero-ish verified counts suppressed while unavailable.

### H.7 Notifications

**[CURRENT]** No delivery substrate exists: the topbar bell has no onClick and no data source (`components/layout/topbar.tsx:30`), the only mailer is password reset (`lib/email/mailer.ts`), and `notificationPolicy` has no consumer (`lib/meta/automation-control-plane.ts:13`). Every dependent design in this study (Monitor push, circuit-breaker alerts, assignment) silently assumed this spine.

**[PROPOSED]** Budget the spine once, explicitly. v1 = **in-app inbox (the bell, made real) + daily digest email**, plus an **immediate channel reserved for the critical class**: automation failure, circuit-breaker trip, kill-switch engagement. Storm rules are part of the contract, not an afterthought: immediate alerts are root-cause-deduplicated (one incident, not N entities) with a per-day storm breaker; the digest groups by action class with true counts and top-3 exemplars, deep-linking into filtered Act Now/History. Notification payloads carry `entityId + snapshotDate + area` so the tap target is resolvable (see H.9).

### H.8 Collaboration and authority

**[CURRENT]** Roles are `admin | collaborator | guest` (`lib/auth.ts:11`) plus a reviewer-email overlay; the owner's Viewer/Analyst/Operator/Admin exists nowhere. Role names freeze-map guest→Viewer, collaborator→Operator, admin→Admin; Analyst is a later narrowing, never a silent regrant. Until tiers land, the UI must state honestly that all write controls share one authority level.

### H.11 High volume

**[CURRENT]** Three verified failure modes. ### I.2 [PROPOSED] Grants, not snapshots

The creator surface is a **new object**, not an audience flag on `creative_share_snapshots` (the "first stage of sharing" framing is rejected precisely because it invites inheriting the leak). Contract `creative_share_grants`:

- `grant_id`, `business_id` (indexed), `created_by`, `recipient_label` + optional `recipient_email` (recipient identity), `creative_ids TEXT[]` (explicit asset scope; never "all current and future" in v1), `metric_tier`, `status ∈ active|revoked|expired`, `expires_at` (default 14d, max 90d, renewal an explicit logged action), `revoked_at`/`revoked_by`.
- Tokens live in a **separate rotatable row** so a token can be reissued without destroying grant history.
- `share_grant_access_log (grant_id, opened_at, ip_hash, user_agent)` replaces the bare `openCount`.
- Payload is **computed at read time within grant scope** — this is what makes revocation and trend possible at all — and every served response records the engine/classification version it rendered.
- Minting authority: `collaborator+` (Operator-tier under the role migration); `guest` never mints. This closes defect 6 on the legacy store too.

### I.3 [PROPOSED] Metric tiers and the privacy boundary

Tier projection is a **serialization boundary**: fields outside the tier are never serialized, not merely hidden.

| Tier | Content | Gate |
|------|---------|------|
| 0 — Creative signals (default) | thumbstop/hook retention, `ctrAll`/`linkCtr`, `video25–100`. Excludes the `cpm`+`impressions` pair (multiplies back to spend) | any grant |
| 1 — Indexed relative outcome | funnel ratios and indexed performance vs an anonymized account cohort ("1.3× account median") — never absolute currency, never target-relative numbers (they reveal whether the brand hits target). The pattern ports from [CURRENT] `peer_comparison` p10/p50/p90 (`lib/meta/evidence-trail.ts:144–148`) | admin-gated |
| 2 — Absolute financials | **does not exist in v1.** Absolute spend/ROAS/CPA never serialize to creator payloads; indexed/relative is the ceiling (D11) | — |

Privacy boundary — a creator must never see, at any tier: absolute spend/revenue/CPA/ROAS; campaign/ad-set names, structure, targeting, audiences ([CURRENT] `SharedCreative` already carries no campaign fields — keep that structural); other creators' identities or performance; raw engine labels (`cut`, `diagnose`), confidence numerals, blockers, `truthSource`, targets; the write ledger (correctly buyer-only today); business identifiers beyond display brand name.

### I.4 [PROPOSED] Winners for creators: trend before status

Internally, D3 ships qualified winner-browse now: "Current winners (vs target)" / "Historical winners" from `engine_v3_decision_snapshots_daily` ([CURRENT] `lib/migrations.ts:5278`; persisted `label`, `raw_label`, `ratio_to_target`, `truth_source`, badges), per engine-version era, chips always truth-source-qualified — the word "Winner" is banned under `global_default`/`account_baseline_thin`, and cohort-relative claims wait for the evaluation-scope object.

Externally, the sequencing is stricter (D11): **creator v1 shows thumbnail, delivery-state, and trend only** — a status timeline read from the same snapshots plus tier-scoped weekly creative-signal series. Status ships second, as a **versioned translation of internal assessment v1** (Section E), never of raw `DecisionLabel`: closed vocabulary `Winning / In testing / Retired / Not enough data`. "Retired," never "Cut" — operator language is relationship-damaging verbatim, and retracting "Winning" from a creator is a trust-destroying event in a way it is not internally, which is why status waits until the internal producer is live and versioned. No cohort claims externally, ever, in v1. The losing position — strategist's "cut the creator surface entirely" — is rejected because it parks the present-tense leak as roadmap; the interaction-architect's trend-first ordering wins over shipping status immediately because status is the uniquely retract-costly artifact.

### I.5 [PROPOSED] Drafted feedback: system drafts, buyer publishes

## J. Launchpad and Automation Maturity Path

### J.1 [CURRENT] Where the ladder actually stands

The honest baseline: **there is no executor.** `execution.autoExecutionAllowed` is computed by the control plane (`lib/meta/automation-control-plane.ts`) and consumed only by the Automation UI (`app/(dashboard)/platforms/meta/automation/automation-view.tsx:119, 208, 341` — grep-verified); no scheduler, job, or route writes to Meta without a user HTTP request. Defaults are locked shut (`autoExecutionEnabled: false`, `dryRunOnly: true`), and no code path can set `auto_execution_enabled=true` — the automation POST route accepts only `engage_kill_switch`, `release_kill_switch`, `set_decision_type_mode`. `auto_execute` is unreachable today without manual DB writes.

The write path that does exist is genuinely good in one respect: every mutation in `lib/meta/ads-write.ts` and `lib/meta/launch-write.ts` is write-then-verify, returning first-class `silent_failure` when Meta says OK but the read-back disagrees (`ads-write.ts:655–656, 754–755, 907–908`), with `dryRun` support on every mutation. But the control layer around it speaks **two mismatched mode vocabularies** — readiness tiers `read_only|manual_review|backtest_candidate|auto_execute` and standing modes `manual|semi_auto|auto` per decision type (`MetaAutomationDecisionMode`, `automation-control-plane.ts:58`) — neither of which matches the owner's four modes, and the rendered guardrails (`dailyAutoActionCap: 3`, `perActionSpendCeilingMinor: 5000`, `maxBudgetIncreasePct: 15`, `requireLivePreflight`/`requireRollbackPlan`) are **display-only**: no write path reads any of them. "Scale Budget," the flagship verb, has no write path at all — no budget mutation kind, no prior-state capture; the only budget mutation in the repo is the orphaned bypass in `lib/meta/execution.ts` (below).

### J.2 [PROPOSED] The automation maturity ladder

One mode vocabulary replaces both existing ones, **per action class**: `mode ∈ observe | recommend | approval_required | auto_execute`. "Observe" is reserved exclusively for this axis (D9). Action classes mirror the triage sections and are the same keys guard budgets and circuit breakers debit (D1's safety argument).

- **Rung 0 — approval-based assistant (v1).** Every class at `recommend` or `approval_required`; all provider writes are user-initiated through the Single Write Gateway; Scale Budget renders as a routed manual step with receipt capture. The audit-spine fixes (J.6) land here as release gates.
- **Rung 1 — guardrailed auto-execution (per class).** A class may be promoted to `auto_execute` only through the D14 gates (J.5), preceded by a mandatory shadow window (executor runs the full pipeline with the already-implemented `dryRun: true`, emitting would-have-written receipts) and an activation delay. Enforced-at-gateway guardrails: per-class daily action cap, per-action spend-delta ceiling as a % of trailing-7d daily spend plus an absolute cumulative daily financial-delta budget (a flat €50 ceiling is meaningless at scale and paralyzing at low spend), per-entity cooldown. Demotion is instant and unilateral; promotion is slow and evidenced.
- **Rung 2 — mature autonomy [FUTURE].** Multiple classes at `auto_execute` with per-class circuit breakers, automated orphan-tree reconciliation, out-of-band drift detection. Even here, high-financial-impact or hard-to-reverse operations stay approval-gated (owner pack, kept).

Sequencing is by gates, not dates. Today's evidence already says the top rung is closed: hard-action ECE measured 0.14 against the repo's own 0.05 gate and hard-action calibration cells never reached n≥30 (`docs/creative-decision-center/READINESS_SCORECARD_2026-07-06.md`) — the surface should say exactly that: "gate closed on evidence, not missing evidence."

### J.3 Single Write Gateway

All provider mutations route through one module with a **fixed guard order**: authz → reviewer/capability claims → switches (global → provider → business → class) → mode check → blast-radius (caps/budgets) → idempotency → preflight → execute → verify → receipt. `ExecutionReceipt { actionId, idempotencyKey, actionKind, source, requestedState, previousState, providerResponse, verifiedState, verifiedAt, verdict, decision_snapshot_ref?, rollbackOf?, adsManagerUrl? }` with `verdict ∈ verified_success | silent_failure | failed | unknown_outcome`. `unknown_outcome` is the new first-class state the owner pack omits: a `pending` action-log row older than the verification timeout (crash between POST and verify) renders "outcome unknown — verify in Ads Manager" and blocks re-issue of its idempotency key until an explicit re-verify read — today the 30-second in-flight dedup simply stops protecting it. The receipt UI renders `verifiedState`, never `requestedState`. `lib/meta/execution.ts` is archived under an explicit policy: archived schemas may be copied, archived write paths never.

### J.4 PAUSED-on-create and the Publish-ACTIVE recast

PAUSED-on-create is enforced at the TypeScript type level (`status: "PAUSED"` literals in `MetaLaunchCampaignInput` et al., `lib/meta/launch-write.ts`) — a guarantee no runtime check equals, and a house invariant. The owner's "user may explicitly select ACTIVE before creation" is therefore recast, not implemented literally: **Publish ACTIVE = composite create-PAUSED → activation step**, with the mandatory preflight, budget summary, and typed confirmation attached **at activation** — same UX outcome, invariant preserved. This also fixes a deeper misdesign: since every launch is PAUSED, activation (today `bulk-ad-status` `resume`) is the actual go-live money moment for 100% of launches, yet the pack's preflight rule guards creation, the free step. Activation preflight re-runs the live checks that exist only at creation today (`validateMetaLaunchRequest`: billing status, active pixel, creative rejection — `lib/launchpad/meta-validation.ts`), plus batch caps and scope restriction.

### J.6 Promotion gates (D14 — every floor is hard)

Promotion of a class to a stronger mode requires **all four**, server-checked; violation of any is a hard block:

1. **Minimum runtime-mode sample**: n≥30 per calibration cell per action class; backfill/shadow rows excluded. 2. **Calibration**: ECE ≤ 0.05 per label — the repo's own published gate, currently failed at 0.14.
3. **Financial outcome strata**, read only after attribution maturity: exclude `unknown_outcome` rows, and fix the accrual bias first — outcome accruals (`auto_kpi_7d.v1`-style 7/14-day windows) are read while Meta is still restating attributed conversions, a directional bias that flatters cuts over scales; outcome records must stamp `dataAsOf` vs `accruedAt`.
4. **Critical-error budget**: any `silent_failure` trips the class circuit breaker and freezes promotion; N consecutive `failed` in a class auto-engages the class block; simultaneous trips across ≥2 classes auto-engage the business switch.

Resolution of the evidence-hierarchy dispute: the decision scientist wins — **realized outcomes are the primary external evidence**, because in a single-operator product the same lone human reviews both shadow receipts and live receipts; shadow windows and activation delay (the safety engineer's position) are adopted as additive defenses, not substitutes for outcome evidence. The current gate ignoring sample size and carrying no financial dimension is a blocked-before-automation defect, not a tuning item. Note also that today's `meta_automation_promotion_records` are written by mode *changes*, not evidence-gated proposals — the evidence-bearing promotion object does not exist yet.

### J.7 Kill switch redesign

[CURRENT] "The kill switch" is three unlike mechanisms: the env var `META_ADS_WRITE_KILL_SWITCH` (requires env change + restart; checked in-module in `ads-write.ts:570/677/822/956` but **not** inside `launch-write.ts`, which relies on the route layer only); the UI-operable per-business switch, whose guard **fails open** when its control table is missing (Postgres 42P01 → default-not-blocked, `automation-control-plane.ts:669–714`) and fails closed on other DB errors; and a separate Google Ads "autonomy kill switch" dialect (`lib/google-ads/product-gate.ts`). No automatic trigger exists anywhere; the owner pack's "trigger the global kill switch on critical failure" is impossible as specified. The business switch is also invisible on the Decisions surface and releasable at collaborator level.

[PROPOSED] One **DB-backed switch registry** with explicit scopes — global / provider / business / action-class — each switch observable (state, reason, actor, timestamp), fail-closed for writes on any control-plane read failure, with a post-deploy self-check that verifies control tables exist before writes are allowed (surfaced through the existing `workspaceBanners` pattern). The button states its scope. Authority is asymmetric by design: **engage anywhere** (any authenticated operator surface, including mobile Tier-0 per D5 — stopping is risk-reducing), **release is admin-tier, desktop-only**. Kill-switch × pending-approvals disposition: engaging a switch freezes all `approval_required` items in its scope (approvals cannot execute, clearly labeled "blocked by kill switch"); on release, nothing auto-executes — each frozen item returns to `approval_required` and must pass a fresh preflight, since the world moved while the switch was engaged. ### J.8 Rollback honesty

[CURRENT] No executable rollback exists on the Meta surface: `buildCreativeRollbackPlan` returns string tokens with no executor and no non-test caller (`lib/creative-decision-engine/execution-safety.ts`, "P2 scaffold"); status/bid mutations capture no prior state, so "restore prior state" is uncomputable. Worse, a live counter-pattern already exists in-repo: the Google advisor path (`rollbackSingleMutateInternal`, `app/api/google-ads/advisor-memory/route.ts`) stamps `executionStatus: "rolled_back"` with **no verification read-back** — exactly the behavior the owner rule ("never claim rollback success unless the provider proves it") forbids, and the template any future Meta rollback will copy unless the contract forbids it by name.

[PROPOSED] Rollback is always a **forward inverse action** through the same gateway, with its own write-then-verify receipt linked via `rollbackOf`; the original action renders "rollback verified" only when the inverse receipt is `verified_success`, else `unknown_outcome`. **Creations are non-rollbackable: contain-only** — duplicate, launch, and Promote-to-Main are never offered "Undo"; containment is pause-and-flag ("Pause in Main" for a promotion, which is a medium-risk delivery-shifting creation whose preflight records the target campaign's CBO/ABO state and whose confirmation discloses budget redistribution — D7). History renders "manual inverse action" and "contain-only," never a generic "rolled back," until inverse receipts exist; the Google path is flagged as a pre-existing violation to repair, not a precedent.

### J.9 Audit spine requirements (pre-executor release gates)

Three fixes land **before any executor merges**, as release gates: (a) `MetaAdsActionKind` gains `bid_update` (and later `budget_update`) — today bid writes are logged as `action: "launch_adset"` with `payload_request.operation: "apply_bid"` (`lib/meta/entity-action-routes.ts:488–495`), so the audit spine misclassifies a live action type; (b) the `source` column is actually populated as `ui_manual | automation:<policyVersion>` — `createMetaAdsActionLog` never sets it and the DDL default is `'ui_manual'` (`lib/migrations.ts:1595`), meaning the first executor would stamp machine writes as human ones; (c) every write carries `decision_snapshot_ref` (a bare `recIdOrigin` string is insufficient for outcome joins and promotion containment) and **prior-state capture** (a before-read on bid/status/budget writes), without which impact-aware rollback and inverse actions are structurally impossible. With those in place, the existing create-pending → complete lifecycle (`createMetaAdsActionLog`/`completeMetaAdsActionLog`) plus verify payloads becomes the receipt substrate the gateway formalizes rather than replaces.

## L. Screen-by-Screen Design Specification

This section is written to drive the Claude Design prompt directly. Global contracts apply to every screen: **zoned density** — Card (~96–120px, Act Now only), Row (32px, Monitor), Dense (26px, History/Archive) — is contract-bound, never a user toggle (replaces the shipped `laneDensity: "cozy"|"compact"` boolean, `MetaPlatformPage.tsx:1838`). **Color budget**: one semantically colored element per row — the action chip, tinted by server `consequenceTone` (danger=Cut, caution=Refresh/fatigue, positive=Scale Budget, info=Promote/structural, neutral=Watch/Keep; Promote is never green) — plus at most one shape-differentiated purple machine-agency marker; purple appears only on machine-agency state, never as branding. **Numerals**: IBM Plex Mono `tabular-nums` (already set by the `.ad-console-shell [data-mono]` rule, `app/globals.css:215–217`), three sizes (N1 18px inspector, N2 13px row strips, N3 11px receipts), never tinted; missing values render em-dash, never zero. **Dark theme**: every screen renders in both themes from the same `--adc-*` token system; dark is fixture-only today — zero `--adc-*` dark values exist (the `.dark` block redefines only shadcn oklch vars) — and becomes live only when the dark-token deliverable plus lint gate land (H.10/N); per N.4, visual acceptance requires both themes at 1440×900 and 390×844 per screen, and `consequenceTone` hues must hold ≥4.5:1 contrast in both themes. **Long text** (inherited by every screen, per H.12): entity names middle-truncate — the suffix is the distinguishing part; reason lines clamp to one line on cards with full text in inspector L2; chips never truncate; nothing wraps to a second line inside a card; stress fixtures use real 60–120-character Meta ad names. **Breakpoints**: <720px mobile stack; 720–1439px inspector as focus-trapped overlay (`MetaDrillDrawer.tsx:534–563`); ≥1440px permanently reserved push inspector, reusing committed `useMinWidth(1440)` (`MetaPlatformPage.tsx:1841`). Screens are numbered **L.1–L.12**; `L1/L2/L3` refers exclusively to the evidence inspector's three disclosure layers (H.5). Every state below is tagged **live-wired** (server contract exists at HEAD) or **fixture-only** (must be designed from `test-fixtures.ts`-style fixtures because no producer exists yet).

### L.1 Decisions — Act Now (`/platforms/meta?area=act`)

**Hierarchy (top to bottom).** (1) Topbar: breadcrumbs, date-range picker, status filter, as-of cluster. (2) **Header band**: a single worst-of freshness indicator computed from the named registry of the four real freshness systems — v1 snapshot health (`MetaSnapshotHealth`), v3 `DataHealth.worstTier`, warehouse sync state, target-pack age (the one canonical set, per K.2/M1.10) — each inspectable on expand; the current `pulse.snapshotHealth ?? lanes.snapshotHealth` pick (`decisions-workspace/route.ts:466`) lets pulse mask lanes and must be replaced. `classifyStaleTier(null)` currently returns `"none"` (`data-health.ts:20–33`); unknown freshness renders as an explicit `unknown` tier styled stale-equivalent, never fresh. (3) **Overnight receipt strip**: one row from the digest (`readDecisionDigest()`, `decisions-workspace/route.ts` — label flips, actions with `verifiedCount`/`silentFailureCount`, open anomalies, due deferrals). Any `silent_failure` count > 0 is the loudest element on the page; digest failure (`unavailableReason`) renders as a warning banner — "Last night's writes could not be verified — check History" — never the current muted one-liner (`MetaPlatformPage.tsx:1468–1469`). (4) The sectioned queue. (5) Compact Monitor and Recent Outcomes summary tiles ordered by section exposure, linking into their areas.

**Layout (D12).** Single ranked column, max measure ~880px, at all widths — the two-column layout (owner pack line 26; visual designer's conditional) is rejected: a ranked queue needs one unambiguous scan order, and at 1440 an inspector (~420px) plus two ~490px columns cannot both exist; opening an item would reflow the queue mid-triage. At ≥1440 the right inspector zone is permanently reserved with an empty state ("Select a decision"); opening a card populates it without reflow and marks the card with the existing `meta-row--selected` border. Below 1440 the inspector is the existing overlay drawer. Honest viewport arithmetic at 1440×900: **5 compact cards default; 4 with fact strips; 3–4 when thumbnail cards are present** — the owner's "4–6" is met only in this stated form.

**Sections (D1 — permanent, not transitional).** Act Now is sectioned by decision class: **Integrity fires** (anomalies, tracking, delivery), **Money moves** (campaign/ad-set grain, v1 engine), **Creative rotation** (v3 engine). Sections mirror guard classes and the committed "no fake global rank across engines" doctrine (`MetaPlatformPage` grouped rendering). Section anatomy: header with **pre-cap count** (fixing the shipped circular post-cap counts, where `.slice(0,18)/.slice(0,30)` runs before `counts = arr.length`), an exposure summary numeral (N2 mono), the top-N cards (N=7 default, server-selected per D6), then a **suppression receipt row**: "12 more in this class — 7 below exposure floor, 3 guard-capped (unlabeled), 2 deferred", each reason linking to the matching Monitor segment. Within a section, items order by currency exposure; items with null exposure **promote** into a visible "can't rank — investigate" band at the section top (D8) — the shipped `?? 0` zero-coding of missing spend in the briefing score is a named defect. **Top strip rule**: the cross-section "Top strip" (calibrated composite *selection*, never an interleaved ranked list) renders only after the calibration gates pass (ECE ≤ 0.05; currently 0.14). Until then the strip does not render and **no placeholder slot is reserved** — a permanently empty region trains scanners to skip it (same rationale as D10).

**Card anatomy — Card density (Act Now).** Four lines plus a conditional left rail. **Left rail** (per H.1, same card grammar): the within-section rank position, ordinal only — numeric priority scores never render on cards (D8); fixture-only until server tier+exposure ordering exists, because today's order is the snapshot `ORDER BY` (spend/confidence sort) and an ordinal over a spend sort launders a sort into a ranking — the rail is absent in v1 until that ships. Then: (1) headline — server action verb (`primaryActionLabel`/buyerAction; "Investigate — {named signal}" replaces "Diagnose"; executionAction as suffix CTA per D9) + entity name, single-line truncate; the action chip is the one colored element. (2) Context chips: lifecycle-role outline chip (kind only; source/confidence inspector-only), assessment glyph+word **creative grain only** (D2/D4 — five values, "Can't assess — {named blocker}", ratio suffix "· 0.8x target"), grain chip; `chips.slice(0,3)` + overflow (committed pattern, `MetaActionCard.tsx:383`). Unlabeled/role-conflict is a distinct card *state* — **"Label needed"**, CTA "Label campaign" (E.1/E.5) — louder than a chip, since the guard caps confidence at 0.45 and rewrites semantics. (3) Reason, `line-clamp: 1`, from `rec.why`/`DecisionOutput.reason`. (4) Fact strip, N2 mono: exposure headline (real spend at stake) · ROAS vs target · CPA · purchases · confidence **band as neutral text** — no numeric confidence anywhere on the card (the `?? 0.4` fabricated default and the `confidenceScore.toFixed(2)` aria-label leak at `MetaActionCard.tsx:185` are named defects). **No estimated-impact slot on the card (D10)** — impact is a three-state inspector contract. Creative cards substitute a 48px thumbnail well (fixture-only until `DecisionOutput` gains preview fields — it carries no `thumbnailUrl`/`campaignId`/`adsetIds` today, `lib/creative-decision-engine/types.ts`). Right rail: primary action button gated by server `actionKind` and `riskTier` (missing tier → highest ceremony), Defer, overflow with Reject/Override (each forcing one `reasonCode` chip). Row and Dense densities collapse lines 2–3 into the headline line; Dense drops the fact strip to Spend · label only.

### L.2 Decisions — Monitor (`?area=monitor`)

Row density, grouped by server `watchSegment` (`unlabeled | missing_target | learning | recently_changed | deferred | issues | mid_confidence | insufficient_signal | other`, `WATCH_SEGMENT_META` in `app/api/meta/lane-classify/route.ts:520–578`). **Row anatomy**: entity name · segment chip · **"Waiting on:"** (existing server description) · **"Reevaluates when:"** — populated only from real predicates: mid-confidence → "when evidence clears the act threshold (currently below — Medium)" (threshold-relative wording; the 0.55/0.7/48h literals at `lane-classify/route.ts:442,451,1275` must first be exported as versioned constants or the copy rots); recently_changed → cooldown end timestamp; deferred → `reappearAt`; missing_target/unlabeled → the CTA is the condition ("Set targets", "Label campaign"); learning/insufficient_signal → honest "no fixed date — needs more spend/purchases". Raw scores never appear here (inspector L3 only). **Segments**: Non-sales is a named segment "Out of sales scope" (a cohort boundary, not a filter — `isPurchaseScopedCohort`); Healthy is a collapsible context band with counts, not rows. **Aggregate-grain entries** [PROPOSED]: cohort-imbalance and evidence-shortfall inflow arrives as one aggregate row per cohort ("Test cohort T-12 — winner not declarable: distribution imbalance, needs N purchases"), produced by the existing aggregate builders (`winner_gap`, `fatigue_cluster` in `lib/creative-decision-center/aggregate-builder.ts:124,209`), preventing the "dozens" promise from becoming hundreds of item rows. **Pagination (D6)**: Monitor is a separate cursor-paginated resource with typed filters — the one-payload consensus is overturned because `watching` is the uncapped "rest" partition server-side. Per-segment "show all" reveals with bounded-reveal receipts ("Showing N of M"). States: loading/empty-per-segment/error are live-wired patterns; aggregate rows and reevaluation copy are fixture-only until the producers/constants ship.

### L.3 Decisions — History (`/platforms/meta/history`, new additive route)

Dense density, virtualized (no virtualization library exists in the repo — an explicit dependency to add), cursor-paginated, backed by a read-model union over the five journals (`meta_ads_action_log`, `meta_decision_responses`, `meta_decision_action_outcome_logs`, the two daily snapshot tables, `engine_v3_decision_events`) with **keyed joins** replacing the `evidence-trail.ts` JSON-substring match. **Journal rows are grouped by episode** — prerequisite: date-free `decisionId` episode identity (fingerprints embed snapshotDate today). Row: timestamp · episode kind chip (write / response / label-flip / outcome / structure / rollback, matching H.4's typed entries) · entity · actor (requires the missing user-attribution column on `meta_decision_responses` — responses are anonymous today) · verdict. **Receipt expansion**: request/response payloads, `verifiedAt`, verdict from the four-value set `verified_success | silent_failure | failed | unknown_outcome`; `silent_failure` is rendered loud (danger), `unknown_outcome` caution, never success-styled. **Outcome columns 1/3/7/14d**: 7d (v1) and 7/14d (v3) are live-wired; 1/3d windows are fixture-only (no accrual windows exist). Immature cells render dimmed with an explicit maturity tag ("day 2 of 7 — not yet attributable"), and `unknown_outcome` rows are excluded from any aggregate line — the day-8 immature-attribution accrual bias is a named defect upstream of this display. **Filters**: `kind`, entity, label, date range, free text; the current Archive lane's closed structures move here as `kind=structures` (1,071 rows on the live account; today the client silently caps at 30, `MetaPlatformPage.tsx` HEAD:3444). **Rollback state** — fixture-only (no executable Meta-side rollback exists: no executor, no prior-state capture): rows render **"manual inverse action"** or **"contain-only"** per J.8, never a generic "rolled back"; a row may show "rollback verified" only when a linked inverse receipt (`rollbackOf`) is `verified_success`. The Google-path counter-pattern — `rollbackSingleMutateInternal` stamping `rolled_back` with no verification read-back — is the render this state must never reproduce. **States**: loading (cursor skeleton), empty journal ("no decision history yet — first snapshot pending"), error with retry — all live-wired patterns. **Replay entry point**: every row carries "View decisions as of this day" opening L.5 pinned to that row's snapshot date.

### L.4 Evidence inspector (shared by L.1–L.3, L.6)

Three strictly additive layers. **L1** — the card's one-line reason (repeated as the inspector header with full entity name). **L2 (default open)** — verifiable facts: structured metric table, 28d ROAS sparkline (`evidenceTrail.roas_history`), peer comparison p10/p50/p90 with this entity's value, recent changes, near-miss blockers rendered from `DecisionPredicateBlocker` ("Needs N more purchases…", `lib/creative-decision-engine/types.ts:638`), outcome precedent (`empiricalOutcomeSummary`). **Every L2 fact carries a provenance chip**: "Meta-attributed" for spend/delivery/attributed conversions, "Shopify" for realized revenue (currently never reaches Meta decision surfaces — until the divergence job exists, revenue wording is always "Meta-attributed revenue"), "GA4 · diagnostic" for funnel facts (never action authority). **L3 (collapsed, "How this was decided")** — the formula view: truth-source chain (`truthSource`, `effectiveTargetRoas`), per-engine confidence-band construction disclosed side by side (v1 categorical `rec.confidence` vs v3 `deriveConfidenceBand` ≥70/40–69, `adapter.ts:304–314`) with the `confidenceSemantics: heuristic_v1 | calibrated_v1` stamp; raw numerals appear here only, labeled "engine score, not a probability"; creative `priorityScore.inputs` breakdown stamped `within_grain_heuristic`; engine version + snapshot date footer. **Estimated impact** is a three-state contract — `unavailable | exposure_proxy | modeled` — and since no field supports `modeled` today, v1 renders the literal "Estimated impact cannot be calculated from current evidence" plus the exposure proxy where real spend exists; scenarios (base/upside/downside) render only under `modeled` [FUTURE]. **Ads Manager links**: rendered only when built from provider-returned ids (`lib/meta/ads-action-routes.ts:69`); the control is absent otherwise; the word "verified" is banned — these links are template-built, never provider-checked. Inspector min-width 380px; decision column min 640px for the long-text state. **Wiring**: the structured metric table, ROAS sparkline (`evidenceTrail.roas_history`), peer comparison, `DecisionPredicateBlocker` near-misses, and the L3 formula fields (`truthSource`, `effectiveTargetRoas`, per-engine band construction, `priorityScore.inputs`) are live-wired; the per-fact provenance chips, the three-state impact contract, and the `confidenceSemantics` stamp are fixture-only until their producers ship.

### N.2 Acceptance criteria per major contract

[PROPOSED] Each new contract lands with tests in the same style as the engine's golden/invariant suites — table-driven fixtures, versioned, run as pre-change gates.

**Taxonomy projection (`decision-classification.v1`).**
- Determinism: same snapshot input + same `vocabularyVersion` → byte-identical `{lifecycleRole, assessment, action, consequenceTone}` output, asserted over a golden fixture set with at least one case per emitted assessment value — including `above_target_scale_blocked` (derived from persisted `label='keep'` + `raw_label='scale'`) and `fatigued_former_winner` (fatigue state + winner history).
- `cannot_assess` always carries a named blocker; the string "Uncertain" never appears in any output (negative assertion).
- Version bump re-derives overlays without touching raw snapshot columns (immutability test: raw rows byte-equal before/after re-projection).
- Rows outside the v2.1 bridge (`keep`, `out_of_scope`) still receive an overlay (regression against the attach-to-bridge failure mode).

**Selection contract / suppression receipts.**
- Sum invariant: for every section, `counts = shown + suppressed`, with `counts` computed pre-cap — a fixture with 203 actionable creatives must return N=7 shown, 196 suppressed with per-reason receipt, count 203 (fixes the circular post-cap counts in `lane-classify/route.ts:1316,1335`).

- Exhaustive mapping test: each tier maps to exactly one confirmation ceremony (popover confirm / typed modal / Launchpad preflight route); `riskTier: undefined` → highest ceremony + "risk unclassified" copy. A fixture proving a high-exposure creative action without a tier cannot reach the light ceremony.

**Receipts.**
- Verdict coverage: every write path terminates in exactly one of `verified_success | silent_failure | failed | unknown_outcome`.
- **Crash test for `unknown_outcome`:** a harness that kills the process between provider POST and verify read must leave the action-log row in `unknown_outcome` — never `success`, never lost. This is the dangerous class today (crash-between-POST-and-verify has no verdict).
- No receipt row may claim rollback/retry success without a provider-verified read (extends the write-then-verify pattern; regression against the Google-path stamp-without-verify defect).

**Promotion gate (D14) — refusal tests.**
- n<30 in any calibration cell → promotion refused with the sample named.
- ECE > 0.05 for any label → refused; the current published 0.14 must fail this test as-is (the test is honest only if it fails on today's data).
- Any `silent_failure` in the class → breaker trips, promotion frozen; a subsequent all-green run does not auto-unfreeze without operator action.
- Backfill/shadow rows excluded from sample counts (fixture with mixed provenance).

**Share links.**
- Revocation-at-read: setting `revoked_at` invalidates the token on the **next read**, before expiry (today a leaked token is irrevocable until expiry — grep-verified no revoke path).

### O.1 Register of rejected or modified assumptions
