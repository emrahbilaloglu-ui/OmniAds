# Retained native reader and closed-day lifecycle

D146 adds a source gate before expanding the exact evaluation/context archive
pilot. The previous campaign-context column token counts could miss a new
whole-table reader or a changed date/selection predicate with the same count.
The ledger now pins complete UTF8 source hashes and explicit consumer roles
across app, components, lib and scripts, including CJS/JS/SQL/Python operator
sources. New, missing or changed literal/central-alias/split-prefix references
refuse. Updating a hash requires reviewing its actual selection and retention
semantics; the generator is not a blanket reader-closure approval.

Keep **every retained snapshot** and its evaluation/context lineage, across old
days, epochs and latest-serving winners. Stability, backtests, outcome windows,
episode history, assigned-account freshness, proposals, thumbnails and readiness
depend on that history. An old date or superseding generation never authorizes
snapshot pruning. Operator action/workflow/proposal/launch lineage, original
generation reuse dependencies, every incoming FK, shared contexts and unknown
non-FK consumers continue to veto selected source removal. Original job receipts,
calibration parents, shared input evidence, shared campaign objects and provider
roots stay live; no shared-object GC or decision identity normalization occurs.

The pure lifecycle assessor accepts only the exact v2 SELECT-only measurement
bound to the ledger digest, a genuinely closed UTC day and zero measured pins.
It returns only eligibility for bounded archive preparation. Unknown operational
consumers refuse even with a matching source hash. Empty lists do not prove all
live/transitive/dynamic readers. All provider/removal/reclaim authority remains
false, with physical bytes reclaimed zero. No production caller, scheduler,
eviction, migration, historical rewrite or fallback reader is installed.

Actual production archive/removal still requires exact deployed consumer
identity, fresh independent FK/non-FK/transitive scope and original job/member
closure, durable original encrypted copies on existing separate storage,
independent original-ID/clock/full-byte restore and actual historical HTTP
readback. Bounded retirement must preserve all retained roots, measure source
absence and reusable physical space, and demonstrate a finite generation/date
lifecycle with observed growth or explicit capacity refusal. Regular VACUUM may
make dead space reusable without lowering database size; neither source hashes,
logical absence nor temporary index shrink closes sustainable storage.
