## Packing, selection and unchanged bounds

Packing first verifies the complete independently trusted original. Deterministic
evaluation-ID subdivision measures actual decoded/compressed bytes; no assumed
250-row threshold. Individual oversized evidence/complete-parent closure refuses
the whole capture. Parts retain original raw JSONB UTF8 text, NULL/reference
representation, arbitrary-precision numbers, IDs, hashes and microsecond clocks.
Repeated original/shared/parent rows must have identical bytes on reassembly.

Runtime caps remain8MiB decoded,2MiB compressed,256KiB response,5s worker,
128MiB old/16MiB young heap and4MiB stack. Offline whole reconstruction keeps
the existing64MiB ceiling; it is not a runtime decompression allowance. The

catalog entries carry its digest plus exact selected evaluation IDs. Returned
in-memory entries attach only that independently trusted root for the worker.
GCM AAD binds root/selection digests as well as original payload/manifest trust.

Catalog publication rejects missing/overlapping memberships, repeated roots,
mixed whole/fragment generation entries, unsupported root metadata, foreign
generation/account scope, unsafe pointers and overflow. Original v1/v2 duplicate
generation refusal remains. One request selects exactly one object using
tenant/generation/evaluation. The worker does not fetch other parts, DB or S3.
Original historical response v2 and review-only UI semantics remain; no Apply,
Cut, current decision or provider authority is introduced.

Missing, corrupt, oversized or dirty published evidence returns unavailable409
through the existing reader/route, not incomplete historical_available, truncated
